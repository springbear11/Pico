# 产品项目与扫码路由

## 1. 目标

产品路由不再只选择一个测试脚本，而是选择一个完整的“产品项目包”。一个项目包同时
包含测试流程 `Sequence` 和设备配置 `StationSystem.json`。因此切换产品时，流程和
设备配置会一起切换，不会出现新脚本沿用上一个产品 Station 的情况。

## 2. 推荐目录

```text
PicoATE.UI.exe
ProductRouting.json
plugins/
  PluginRegistry.json
projects/
  Charger_A/
    charger_a_sequence.json
    StationSystem.json
    image/
  Charger_B/
    charger_b_seq.json
    StationSystem.json
```

每个 `projects/<产品名>/` 目录必须满足：

- 必须有一个 `StationSystem.json`。
- 必须且只能有一个文件名包含 `sequence` 或 `seq` 的 JSON 测试脚本。
- 图片等项目资源可以继续放在项目目录内。
- 共用插件仍放在程序根目录的 `plugins/`。项目内 Station 统一写
  `plugins/PluginRegistry.json`；Core 会先检查 Station 同级目录，再向上查找最近的
  程序包根目录，因此产品目录层级变化时不需要改 `../../`。

如果目录里没有 Sequence、缺少 Station，或者同时出现两个 Sequence 候选，项目会被
标记为不可运行，不会靠“随便取第一个文件”继续执行。

## 3. ProductRouting.json

```json
{
  "allowManualInTest": false,
  "projectRoot": "projects",
  "routes": [
    {
      "name": "800V Charger",
      "pattern": "*C1234567*",
      "project": "Charger_A",
      "enabled": true
    }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `allowManualInTest` | 是否允许 Test 模式手动选择产品项目 |
| `projectRoot` | 产品项目根目录，相对路径以 `ProductRouting.json` 为基准 |
| `name` | 路由显示名称 |
| `pattern` | SN 通配规则，支持 `*` 和 `?` |
| `project` | `projectRoot` 下的产品目录名称 |
| `enabled` | 是否参与扫码匹配，默认 `true` |

旧版 `sequence` / `sequencePath` 路由仍可读取。旧路由会从 Sequence 所在目录寻找
`StationSystem.json`；新建路由统一使用 `project`。

## 4. 登录行为

- Manual 模式枚举 `projects` 的一级子目录，登录页只显示产品名称；选中一个产品后，
  Sequence 和 Station 同时确定。
- Auto By SN 模式登录时不预加载各产品脚本。扫码后 Core 先匹配路由，再解析该项目
  的 Sequence 和 Station，随后校验该 Station 的 SN 规则并编译运行。
- Auto By SN 的扫码输入框不得套用当前已加载 Station 的 `snPattern`、`snLength` 或
  `snAllowedRegex`。这些规则只在路由命中后从目标 Station 读取，避免上一产品的规则
  拦截下一产品的 SN。Manual 模式仍直接使用当前 Station 的规则。
- Test 和 Admin 使用同一套项目解析和路由规则。
- `QSettings` 分别记住 Test/Admin 的加载模式和上次手动选择的产品。
- 没有 `projects` 目录时，旧版根目录平铺的 Sequence + Station 仍可手动运行，便于逐步迁移。

## 5. 路由与设备配置界面

Test 和 Admin 的 `Routes / Product Routing` 按钮打开同一个配置窗口，Test 不要求
Admin 密码。表格包含：

- Enabled
- Product / Route
- SN Pattern
- Project
- Device Status
- Devices

每一行的 `Configure` 按钮会打开该项目自己的 `StationSystem.json`，可枚举并保存 CAN
序列号、VISA 资源、COM 口或 TCP/IP 信息。设备信息仍只写入 Station，
`ProductRouting.json` 只保存 SN 到项目的映射。多个路由指向同一项目时自然共用同一份
Station。

设备配置会立即保存到对应项目 Station；路由表中尚未保存的文字修改仍保留在弹窗中。
测试运行期间禁止修改路由或设备，新的配置从下一次扫码生效。

## 6. 匹配和运行约束

- 每个 SN 必须恰好命中一条已启用路由。
- 没有命中或命中多条都不运行，并显示明确原因。
- 两条可能匹配同一 SN 的规则在保存时直接报错。
- 命中后如果项目目录、Sequence 或 Station 缺失，不创建运行会话，也不计入良率。
- 同一路由连续扫码时可复用已经编译的 Sequence，但每台产品仍有独立运行状态和报告。

## 7. 迁移步骤

1. 在程序根目录创建 `projects`。
2. 为每个产品创建一个子目录。
3. 把该产品的 Sequence 和 Station 放进同一个子目录。
4. 检查 Station 的 `pluginRegistry` 相对路径。
5. 在 Product Routing 窗口将旧 `sequence` 路由改选为对应 Project 后保存。
6. 分别用 Manual 和 Auto By SN 各跑一次，确认加载的 Sequence、Station 和设备一致。
