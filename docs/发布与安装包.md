# PicoATE 发布与安装包

当前发布基线：`0.3.0`，2026-09-06。

## 交付物

正式发布会同时生成两种文件：

| 类型 | 输出位置 | 用途 |
| --- | --- | --- |
| Windows 安装包 | `out/installer/PicoATE-Setup-0.3.0-x64.exe` | 项目现场推荐使用，自动创建程序目录和快捷方式 |
| 便携 ZIP | `out/package/PicoATE-Portable-0.3.0-x64.zip` | 解压即用，适合调试、备份和无安装部署 |

两种交付物来自同一个经过校验的 Release 目录，不使用 Debug 构建产物。

## 目标电脑要求

支持以下 64 位系统：

- Windows 10 1809 或更高版本；
- Windows 11。

发布包已经自带：

- PicoATE UI、任务引擎动态库和 NativeHost；
- 独立的 `PicoATE.RegisterImporter.exe` 寄存器配置表转换工具；
- Qt 6.9.1 运行库、平台插件和图像插件；
- Microsoft Visual C++ x64 运行库；
- CAN、DMM、PSU、Modbus TCP 的 PicoATE C++ 插件；
- GCAN 和 CX 插件使用的厂家用户态 DLL；
- `PluginRegistry.json` 和一份空的 Product Routing 配置。

框架安装包不携带任何产品 Sequence 或 Station。安装后会创建空的 `projects/` 目录，产品项目由项目团队单独部署，避免把开发机上的客户脚本带入通用安装包。

当 `projects/` 中没有可用项目时，登录页会显示 `New Project Template`。使用 Admin 模式打开后，系统在内存中创建空的 Sequence 与 Station；首次保存必须执行 `Save New Project As`，输入项目名后一次生成：

```text
projects/<项目名>/
  sequence.json
  StationSystem.json
  register/
```

`register/` 用于保存项目寄存器配置 `.xlsx/.xlsm`，新建项目时自动创建；没有寄存器表的
项目可以保持该目录为空。

内置模板没有磁盘路径，因此普通 Save 不会覆盖安装包文件。也可以随时通过 `File > New Project...` 创建另一份空项目。

空 Station 的默认值为：项目字段 `NA`、SN 字符限制 `^[A-Z0-9]+$`、扫码开启、失败停止开启、TXT/CSV/XLSX 记录开启、循环测试关闭、输出路径为空、设备列表为空。空 Sequence 只包含 Setup、Main、Cleanup 三个标准组，不包含测试项。

目标电脑不需要安装 Qt、Visual Studio、CMake 或 VC++ Redistributable。现场仍需安装与硬件相关的系统驱动或 I/O Runtime：

| 设备 | 目标电脑仍需安装 |
| --- | --- |
| GCAN USB-CAN | 广成 USB 设备驱动 |
| CX USB-CAN | 创芯/ControlCAN USB 设备驱动 |
| VISA DMM/PSU | NI-VISA、Keysight IO Libraries 或兼容的 64 位 VISA Runtime |
| Modbus TCP | 无额外运行库，保证网络和防火墙配置正确即可 |

当前内置项目均走 C++ DLL 插件，不依赖 Python。未来若某个项目脚本主动使用 Python 模块，该项目需要另行部署匹配的 Python 环境。

## 使用方式

安装版：

1. 运行 `PicoATE-Setup-0.3.0-x64.exe`；
2. 按向导完成安装；
3. 安装对应设备驱动或 VISA Runtime；
4. 将待运行项目的 Sequence 与 Station 放入安装目录的 `projects/`；
5. 从桌面或开始菜单启动 PicoATE。

便携版：

1. 完整解压 ZIP，不能只复制 `PicoATE.UI.exe`；
2. 安装对应设备驱动或 VISA Runtime；
3. 将待运行项目的 Sequence 与 Station 放入解压目录的 `projects/`；
4. 运行解压目录中的 `PicoATE.UI.exe`。

## 配置与升级

安装器按当前用户安装到 `%LOCALAPPDATA%\Programs\PicoATE`，通常不需要管理员权限。

覆盖升级时会更新程序、Core、NativeHost、Qt 和插件文件，同时保留：

- `ProductRouting.json`；
- `projects/` 中的产品 Sequence 与 Station；
- `log/`；
- `diagnostics/`。

这些目录在卸载时也会保留，避免误删现场配置和历史记录。需要完全移除时，由工程师确认备份后手工删除。

## 一键构建

构建机需要 VS2022 C++、Qt 6.9.1、CMake 和 Inno Setup 7。进入仓库根目录执行：

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File .\packaging\build_release.ps1 -Version 0.3.0
```

脚本会依次完成：

1. 构建全部 Release 插件；
2. 构建 UI、Core 和 NativeHost；
3. 运行 Release 自动化测试；
4. 调用 `windeployqt` 收集 Qt 依赖；
5. 收集 MSVC Runtime 和厂家运行 DLL，并创建空的 `projects/`；
6. 通过各插件 `PicoATE_Describe` 重新生成 `PluginRegistry.json`；
7. 递归检查 EXE/DLL 导入依赖；
8. 在隔离 `PATH` 下启动并正常关闭 UI；
9. 生成 SHA-256 `package-manifest.json`；
10. 生成便携 ZIP 和安装包。

可用参数：

```powershell
# 使用另一份 ProductRouting；projects 始终不进入框架发布包
.\packaging\build_release.ps1 -Version 0.3.0 -RuntimeSource D:\Project\Runtime

# 只生成便携包
.\packaging\build_release.ps1 -Version 0.3.0 -SkipInstaller
```

正式发布不建议使用 `-SkipTests`。

## 当前验证结果

- Release 自动化测试：CLI、Core、串口发现、寄存器导入及 UI 运行时 `24/24` 通过；窗口测试单独在原生 Windows 环境验证，本次未执行完整窗口套件；
- 便携目录：PE 依赖递归检查通过；
- 发布目录：隔离 `PATH` 下启动、正常退出通过；
- 安装包：Inno Setup 构建通过，版本 `0.3.0`；本次未覆盖本机已有安装，也未执行全新系统或真实硬件验证；
- 插件注册表：9 个插件均可执行 `PicoATE_Describe` 并获得稳定 `moduleId`。
- 项目隔离：安装包和便携 ZIP 中的 `projects/` 均为空。

每次重新发布后，文件哈希会变化，以交付目录内的 `package-manifest.json` 和发布记录为准。

## 已知边界

- 当前安装包尚未使用商业代码签名证书。Windows SmartScreen 或企业安全策略可能显示“未知发布者”；正式大规模部署前应购买代码签名证书并在发布脚本中增加签名步骤。
- “任意电脑可用”指满足上述 Windows x64 版本、企业策略允许运行，并已安装对应硬件驱动的电脑，不包括 Windows 7、32 位 Windows 或缺少厂家驱动的环境。
- 驱动、VISA Runtime 和硬件固件具有厂家兼容性要求，不能仅靠复制 DLL 替代系统级安装。
