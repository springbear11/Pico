# PicoATE 变量与结果引用

## 两个解析阶段

### 配置期变量

配置期变量在加载 Sequence、Station config 和 NativeHost manifest 时解析，常用变量包括：

```text
${PROJECT_DIR}
${SEQUENCE_DIR}
${PICOATE_NATIVE_HOST}
```

配置期解析由 `VariableResolver` 完成，主要用于路径、程序位置和环境配置。

### 运行期变量

运行期变量在每个 Node Attempt 执行前解析：

```text
${uut.id}
${frame.id}
${attempt.index}
${attempt.number}
${loop.index}
${loop.value}
${sn}
${serialNumber}
${uut.sn}
${uut.serialNumber}
${var.serialNumber}
```

完整字符串表达式保留原始 QVariant 类型；嵌入普通字符串时转换为文本。

### Sequence 类型化变量

项目测试参数保存在 Sequence 根节点的 `variables` 数组中，而不是写入 Station：

```json
{
  "variables": [
    {
      "name": "CAN_ID",
      "type": "hex",
      "scope": "perUut",
      "values": ["0x101", "0x102", "0x103", "0x104"]
    },
    {
      "name": "PRODUCT_FAMILY",
      "type": "string",
      "scope": "shared",
      "value": "BTS"
    }
  ]
}
```

- `shared`：所有 UUT 使用同一个 `value`。
- `perUut`：UUT1 至 UUT4 分别使用 `values[0]` 至 `values[3]`。
- 支持 `string`、`integer`、`hex`、`double`、`bool` 五种类型。
- Step 中统一写 `${var.CAN_ID}`；当前 UUT 的数组位置由 Core 自动选择。
- UI、CLI 和 Core 测试共用 `bindSequenceVariablesForUut()`，不会出现入口间语义不同。
- 若某个运行槽位没有值，运行准备直接报告变量名和 UUT 编号，不会误用其他槽位的值。

Flow Editor 工具栏的 `Variables` 打开变量表；修改先进入 Sequence 内存草稿，最终仍由
`Ctrl+S` 或 Save 写回当前 Sequence JSON。属性编辑器的 `fx` 菜单会列出这些变量，避免手写表达式。

扫码通过后，UI 会把原始 SN 同时写入根作用域 `sn/serialNumber` 和当前 UUT 作用域
`uut.sn/uut.serialNumber`。四种写法当前值相同；推荐业务脚本使用 `${uut.sn}`，因为它明确表达
“这是当前 UUT 的序列号”，多 UUT 扩展时也不容易混淆。`${sn}` 保留给已有脚本和简短配置。

## 作用域 Step 地址

顶层 TestItem 和独立 Step 可以使用三位字符串 ID：

```json
{ "id": "001", "name": "CAN请求" }
```

TestItem 内子步骤可以同时使用局部 ID 和语义 Key：

```json
{ "id": "03", "key": "rx", "name": "接收响应" }
```

编译后节点路径：

```text
001.rx
```

规则：

- ID 必须是 JSON 字符串，`"001"` 不能写成数字 `1`。
- 顶层节点 ID 在整个 Sequence 中唯一。
- 子步骤 ID 和 Key 只需在同一个父节点下唯一。
- ID/Key 创建后不因插入、删除或排序而自动重编号。
- ID/Key 不允许包含 `.`。
- `outputs`、`measurements`、`outcome` 是保留 Key。
- 执行顺序由数组和图边决定，与数字大小无关。

## Step 结果表达式

跨 TestItem 使用完整路径：

```json
"frame": "${step:001.rx.outputs.frame}"
```

当前 TestItem 内使用相对 Key：

```json
"actual": "${step:parse.outputs.voltage}"
```

读取结果状态：

```json
"rxOutcome": "${step:001.rx.outcome}"
```

读取测量结果：

```json
"firstMeasurement": "${step:001.rx.measurements.0}"
```

## Flow Editor 自动维护引用

Flow Editor 会在结构编辑时同步维护 Step 地址，避免复制或拖动后逐项手改：

- 复制顶层或嵌套 TestItem 时，会给副本生成新的同级 ID，并重写副本内部指向原子树的完整路径和局部路径。
- 将 TestItem 或 Step 拖到另一个父级时，会根据新父级重新计算完整节点路径。
- 被移动子树内部的自引用会更新；流程中使用完整路径指向该子树的外部引用也会更新。
- 指向子树之外其他 Step 的表达式保持不变，不能因为复制而悄悄改成副本。
- 修改先进入 Sequence 草稿，仍由 `Ctrl+S`、Save 或 Compile 统一写回 JSON，并支持 Undo/Redo。

例如把 `001.first` 复制到同一父级并生成 `001.03` 后：

```text
${step:001.first.rx.outputs.value} -> ${step:001.03.rx.outputs.value}
${step:01.rx.outputs.value}        -> ${step:03.rx.outputs.value}
${step:900.outputs.value}          -> 保持不变
```

## ExecutionResultStore

每个 `ExecutionSession` 持有一个 `ExecutionResultStore`，存储键包含：

```text
UutId + FrameId + NodePath
```

因此两个 UUT 同时运行 `001.rx` 时，读取到的始终是各自结果。

仓库行为：

- 普通 Step 保存最终 NodeResult。
- Retry 保存每个 Attempt 历史，默认引用最新结果。
- Loop body 保存每轮结果，Loop 结束后默认引用最后一轮。
- `outputs` 和 `measurements` 默认只允许读取 Passed 源结果。
- `outcome` 可以读取任意已完成源结果。
- 大型波形和抓包文件应保存为 Artifact，outputs 中只返回路径和摘要。

## 编译期失效检查

编译器会拒绝：

- 节点不存在
- 表达式格式错误
- 自引用
- 引用未来节点
- 无法保证源节点先执行
- 同级 ID/Key 重复
- Key 使用保留字段

有效引用会生成 `condition = step-result` 的数据依赖边。

## 运行期失效检查

运行期可能返回：

| 错误码 | 含义 |
|---|---|
| `StepReferenceNotFound` | 节点地址不存在 |
| `StepResultUnavailable` | 源节点尚无结果 |
| `StepResultNotPassed` | 源节点 Failed/Error/Timeout/Skipped |
| `StepResultValueNotFound` | outputs/measurements 中不存在目标字段 |
| `RuntimeVariableResolutionError` | NodeRunner 汇总的变量解析错误 |

完整示例见 `examples/scoped_result_sequence.json`。

Sequence 变量示例见 `examples/sequence_variables.json`。
