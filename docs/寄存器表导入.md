# 寄存器表导入

## 用途

Flow Editor 的“导入寄存器表”按钮用于把项目寄存器 Excel 表自动转换为可执行测试流程。
转换后的固定顶层测试项为：

```text
MAIN
└── register_config  寄存器表配置写入
    └── Excel 分页
        └── 寄存器参数
            ├── FC10 写入
            ├── Wait 20 ms
            ├── FC03 回读
            ├── Decode Modbus Registers
            └── Limit equal 校验
```

只读参数不生成 FC10 和 Wait，只生成 FC03、解析和 Limit。

## 项目目录

当前 Sequence 所在项目目录下使用小写 `register` 文件夹，可保存一个或多个待导入的
`.xlsx` 或 `.xlsm` 文件：

```text
projects/<项目名>/
├── sequence.json
├── StationSystem.json
└── register/
    ├── 机型A寄存器配置表.xlsx
    └── 机型B寄存器配置表.xlsx
```

新建项目时 UI 会自动创建 `register`。旧项目中的 `Register` 仍可被大小写兼容识别。
临时文件 `~$*.xlsx` 会自动忽略。旧 `.xls` 格式不支持，需要先另存为 `.xlsx`。
点击导入后，Flow 会在弹窗中枚举这些工作簿；选中一份后点击“导入”，点击“取消”则
不会启动转换，也不会修改当前 Flow。

## Excel 表头

列顺序不限，按表头名称识别：

| 表头 | 必填 | 说明 |
|---|---|---|
| 起始地址 | 是 | 必须是带 `0x` 前缀的十六进制文本，范围 `0x0000` 到 `0xFFFF` |
| 参数名称 | 是 | 流程和报告中的可读名称 |
| 数据类型 | 是 | `U16`、`U32`、`U64` 或 `int` |
| 寄存器数 | 否 | 可由明确的数据类型推导；`int` 必须填 1、2 或 4 |
| 功能 | 是 | `R/W` 或 `R` |
| 寄存器值 | 是 | 物理期望值，不是换算后的原始寄存器值 |
| 偏移 | 否 | 默认 0 |
| 缩放比例 | 否 | 默认 1，不能为 0 |

写入原始值按下式生成：

```text
原始寄存器值 = (物理期望值 - 偏移) / 缩放比例
```

结果必须是整数并且不能超出数据类型范围，否则整次导入失败。

## 分页 ID 与 unitId

| 分页名称包含 | 固定分页 ID | unitId |
|---|---:|---|
| M2系统监控 | `001` | `0x0F` |
| CCU终端共用 | `002` | `0x01` |
| MCU主控板 | `003` | `0x00` |
| 其他名称 | 从 `004` 起分配 | 默认 `0x00`，导入后给出警告 |

已知分页 ID 不依赖 Excel 中的分页顺序，因此重新排列分页不会改变生成步骤的引用地址。

## Flow 操作

1. 在 Admin 模式打开目标项目的 Sequence 和 Station。
2. 进入 Flow Editor，点击工具栏中的表格图标“导入寄存器表”。
3. 在弹窗中选择一份 Excel，点击“导入”；“取消”不会改变脚本。
4. 若 Station 只有一个已启用的 MODBUS 设备，自动写入该逻辑 ID。
5. 若存在多个 MODBUS 设备，再选择本次配置表使用的设备。
6. 后台进程读取 Excel；成功后将生成块放到 MAIN 第一项。
7. 检查 Flow 后按 `Ctrl+S` 保存。导入本身不会绕过草稿保存规则。

弹窗会通过 `QSettings` 记住上一次导入的工作簿；再次打开同一项目时优先恢复该选择。
如果上次文件已不存在，则回退到当前 `register` 文件夹中的第一份工作簿。

再次导入会完整替换旧的 `register_config`，不会在 MAIN 中重复追加。整次替换只产生一条
Undo 记录，可一次撤销恢复原配置块。Sequence 顶层变量和其他测试项保持不变。

## 安全边界

- Excel 解析由工具根目录的 `PicoATE.RegisterImporter.exe` 独立进程完成，UI 不直接解析工作簿。
- 工具根目录不存在 `PicoATE.RegisterImporter.exe` 时，Flow 不显示“导入寄存器表”入口。
- 十进制地址（如 `40961`）和缺少 `0x` 前缀的地址会阻断整次导入，不会自动猜测进制。
- 转换期间 Flow 若被编辑，返回结果不会覆盖新修改，需要重新导入。
- 任意表头、地址、类型、功能、缩放或数值错误都会阻止整个配置块写入。
- `register_config` 若被 Setup/Cleanup 顶层占用，会拒绝覆盖并提示冲突。
- 生成后仍需正常点击 Compile；首次接真实产品前应复核 unitId、地址、写值和回读值。

## 架构定位

寄存器表导入属于平台的**设计期工具扩展**，不是运行期测试 Step，也不是调度引擎能力：

- UI 只负责选择工作簿、启动外部工具，以及将返回的 TestItem 草稿插入 Flow。
- `PicoATE.RegisterImporter.exe` 独立完成 Excel 读取、校验和 JSON 生成。
- Core 只在正常 Compile/Run 时消费生成后的 Sequence JSON，不依赖 Excel 或导入器。
- 因此导入工具异常退出不会污染调度引擎；移除该工具也不影响现有 Sequence 的执行。

## 当前真实表验证

参考表 `C66766035 2.5M二十枪机型配置表.xlsx` 已验证：识别 3 个分页、12 个参数，
生成 76 个执行节点并通过 `SequenceCompiler`。例如堆功率 2500、缩放比例 1，生成写值
`[0x0000,0x09C4]`。
