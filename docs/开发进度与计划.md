# PicoATE Progress Plan

## 2026-06-20 起始总结

项目从架构文档推进到了可编译、可测试的 PicoATE 调度内核 MVP。当前代码已经形成了完整的第一条闭环：

```text
JSON -> SequenceDef -> PlanBuilder -> ExecutionPlan -> ExecutionSession
```

## 2026-06-22 今日总结

今天完成了三块对“配置化交付”非常关键的能力：

| 事项 | 结果 |
|------|------|
| LoopController For 循环 | 固定 `for` 循环进入调度层，业务模块不需要知道循环语义 |
| VariableResolver 中心化 | 统一 `${PROJECT_DIR}`、`${SEQUENCE_DIR}`、显式变量、环境变量和递归替换 |
| NativeHost manifest | DLL 路径、symbol、buffer size、timeout 从命令行参数迁移到 manifest JSON |

历史详细记录已合并到 [开发日志](开发日志.md)。

## 当前结论

PicoATE 已经不只是架构文档，当前具备一个可编译、可测试、可从命令行运行 JSON sequence、能输出只读 ExecutionReport、能通过 `IModule` 执行业务动作，并为外部模块隔离提供 `IModuleTransport` 适配边界的调度内核。项目最终目标已记录在 `docs/项目愿景与边界.md`：UI、任务调度、业务测试逻辑三层解耦；项目交付时优先通过 JSON/config 配置流程和新增底层业务模块完成，避免修改 UI 和调度框架。Qt Runner、Sequence/Station Editor、实时事件、报告历史、安全连接测试、调试能力、Timeline 联动，以及窗口/分栏/页签/运行参数持久化、最近文件和默认布局恢复已经落地。双模式 UI 已完成 TEST 第一版和结果列补齐；下一步重排 Admin 工作台，再进入插件功能目录、拖拽编排和发布打包。UI-TECH-001 按当前决定暂缓，真实项目驱动、崩溃恢复和干净机器发布验证仍是后续工作。

Pause/Resume 为协作式安全点：运行中的 Step 会先正常返回并释放节点资源，Session 随后在下一次 `pumpOnce` 前进入 Paused；暂停不会清空 Barrier、等待队列或 UUT Activation。暂停期间 Stop/Abort 会唤醒执行线程并继续既有 Cleanup 语义。

Breakpoint 复用同一个安全点：命中后停在目标 Step 执行前，支持内部唯一 `nodePath` 和人可读 `localPath`（如 `001/03`）。Debug Snapshot 是只读值拷贝，包含当前 UUT/Step、变量、节点状态、attempt、ResourceSnapshot 和 BarrierSnapshot，UI 只能展示，不能修改调度内部状态。Run 页右侧的 Debug tab 已可显示这份快照；Sequence 树的 BP 列可以勾选临时断点，Run 前同步为 `BreakpointSpec`，断点命中后会自动定位并高亮当前 Step。Timeline tab 显示非日志 RuntimeEvent 顺序，用于观察 Node、Attempt、Loop、Barrier、Retry、断点和单步事件；点击 Timeline 某个 Step 事件会同步选中结果树和 Sequence 树，断点命中/单步暂停也会自动选中对应 Timeline 行；高频业务日志仍留在 Logs tab。Step Into 会执行一个调度节点后暂停；Step Over 对普通节点等同单步，对 Loop/TestItem 这类结构节点会跑完整个结构块再暂停。
