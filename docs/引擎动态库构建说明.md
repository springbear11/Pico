# 引擎动态库构建说明

## 目标

`PicoATECore` 已由静态库改为 Windows 动态库。UI、CLI、NativeHost 和测试程序在编译时链接其导入库，在运行时加载 `PicoATECore.dll`。

当只修改引擎内部实现，并且公开头文件和二进制接口没有变化时，可以只编译 `PicoATECore`，不重新编译 UI。Core 构建完成后会自动把 DLL 更新到各程序对应的 Debug 或 Release 目录。

## 构建命令

首次生成 VS2022 总解决方案：

```powershell
cmake --preset vs2022-qt6-all
```

只编译 Debug 引擎：

```powershell
cmake --build --preset vs2022-qt6-core-debug
```

只编译 Release 引擎：

```powershell
cmake --build --preset vs2022-qt6-core-release
```

在 `PicoATE.All.sln` 中也可以单独选择 `PicoATECore` 项目执行“生成”。

## 主要产物

引擎原始产物：

```text
out/build/vs2022-qt6-all/src/core/Debug/PicoATECore.dll
out/build/vs2022-qt6-all/src/core/Release/PicoATECore.dll
```

UI 运行目录中的部署副本：

```text
out/build/vs2022-qt6-all/ui/src/Debug/PicoATECore.dll
out/build/vs2022-qt6-all/ui/src/Release/PicoATECore.dll
```

CLI、NativeHost 和测试程序目录也会获得同配置的 DLL。Debug DLL 只能配 Debug 程序，Release DLL 只能配 Release 程序，不能混用。

## 哪些改动只需替换 DLL

- 修改调度算法、错误处理、循环、Barrier、报告等 `.cpp` 内部实现。
- 修复内部逻辑，但不改变公开类、结构体、函数和枚举的声明。
- 增加只在 Core 内部使用的私有函数或私有实现。

## 哪些改动仍需重新编译 UI/CLI

- 修改公开头文件中的函数签名。
- 修改公开类或结构体的成员布局、继承关系、虚函数表。
- 修改 UI/CLI 直接使用的枚举、模板或内联函数。
- 更换 Qt、MSVC 工具链、运行库选项或 C++ ABI。
- 在 Debug 与 Release 之间切换。

当前 DLL 边界仍然是 C++/Qt ABI，适合在同一套 VS2022、Qt6 工具链内减少重复编译，但不承诺跨编译器或跨 Qt 版本兼容。`CoreExport.h` 已预留显式导出宏；现阶段使用 CMake 自动导出兼容现有较大的公开接口，后续会逐步收敛公开服务接口并减少二进制耦合。

业务插件仍通过 PicoATE 插件 ABI/NativeHost 接入，不应直接链接 `PicoATECore.dll`。这样项目业务 DLL 与引擎内部 C++ ABI 保持隔离。
