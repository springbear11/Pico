# PicoATE ExecutionReport 存储格式

版本：V3  
日期：2026-07-01

## 1. 用途

`ExecutionReport` 是内存中的只读结果模型。UI 内部仍用 JSON 保存历史索引和历史详情，
但 JSON 不再作为产线人员直接使用的报告格式。对外报告统一为实时 TXT 日志和最终 CSV。
它不是运行会话快照，不能用于断点恢复，也
不包含正在运行的 `ExecutionSession`、设备连接或资源租约。

## 2. 顶层格式

```json
{
  "schema": "picoate.execution-report",
  "schemaVersion": 3,
  "report": {
    "planId": "...",
    "sequenceId": "...",
    "sequenceVersion": "...",
    "state": "Completed",
    "completed": true,
    "hasError": false,
    "uuts": []
  }
}
```

`schemaVersion` 是文件兼容边界。当前读取器接受 V1、V2 和 V3；V2 新增
`StepReport.children` 保存复合测试项层级。遇到未知更高版本时明确报错，不会猜测
字段含义。缺少可选数组或可选属性时使用空值。

V3 新增 `StepReport.nodePath`。`stepId` 保存当前作用域内的局部 ID，例如 `03`；
`nodePath` 保存编译后的唯一地址，例如 `001.rx`。UI 默认显示局部 ID，历史对账、
RuntimeEvent 和结果仓库使用 `nodePath`。

V3 读取器还支持可选的 `StepReport.phase`，取值为 `Setup`、`Main` 或 `Cleanup`。
它用于 TEST 页面按执行阶段分区，来自编译后的 Plan；旧报告缺少该字段时按 `Main`
处理，因此不提高 schemaVersion，也不影响已有历史报告读取。

## 3. 数据层级

```text
ExecutionReport
  UutReport[]
    StepReport[]
      children[]             # testItem/loop child steps
      AttemptReport[]
        LoopIterationContext
        MeasurementResult[]
      MeasurementResult[]
```

Measurement 保存 value、rawValue、unit、上下限、判定、错误和 attributes。JSON
加载后不重新计算 Pass/Fail；文件中的报告结果就是历史事实。

## 4. 历史目录

Runner 默认保存到 Qt `AppLocalDataLocation/history`：

```text
history/
  index.json
  20260629-203000-123-a1b2c3d4.json
```

报告和索引均使用 `QSaveFile` 原子替换。`index.json` 损坏或丢失时，Runner 会扫描
目录内有效的 ExecutionReport 文件重建索引；无法解析的损坏报告不会进入历史列表。

## 5. 对外 TXT 日志

TXT 与 TEST/Admin 界面的执行日志使用同一个格式化数据源，不重新拼装另一套日志。
测试开始时就创建文件，每批 RuntimeEvent 到达 UI 后立即追加并 `flush`。典型内容：

```text
[14:52:01.001] ======================== CAN_CHECK_TESTITEM_START ========================
[14:52:01.002]     ------------------------ READ_CAN_STEP_START ------------------------
[14:52:01.008] LOG:RX 01 02 03
[14:52:01.010] RESULT:PASS
[14:52:01.010]     ------------------------ READ_CAN_STEP_END ------------------------
[14:52:01.011] RESULT:PASS
[14:52:01.011] ======================== CAN_CHECK_TESTITEM_END ========================
```

TestItem 的开始/结束会包在子 Step 外层，缩进与界面保持一致。这样即使测试过程很长，
程序意外退出前已经写出的诊断信息仍然保留。

TestItem 使用对称长等号边界；相邻 TestItem 之间保留三个空行。子 Step 使用对称长横线
边界，START/END 放在中间；同一 TestItem 的子 Step 之间不插空行，便于连续追踪通信、
等待、接收和解析过程。

## 6. CSV 与 XLSX 报告

CSV 使用 UTF-8 BOM 和 CRLF，方便 Excel 直接打开中文。每行对应一个测试项测量结果；
没有 Measurement 的 Step/TestItem 仍保留一行。固定列为：

```text
Test Item, ERRORCODE, Lower Limit, Upper Limit,
Actual Value, Test Result, Duration Ms
```

有多项 Measurement 时，同一个测试项可以出现多行。结果和用时取 Step 最终结果，
ERRORCODE 优先取 Measurement，否则取最后一次 Attempt。

XLSX 与 CSV 使用相同的七列和同一份结果数据，不重新计算判定。XLSX 额外提供固定表头、
自动筛选、合适列宽以及 PASS 绿色、FAIL/ERROR 红色、SKIPPED 灰色行底色；文件由程序
直接生成，不要求工位电脑安装 Excel，也不增加运行时 DLL。

上下限按比较方式统一生成：

- `between`：写入配置值，或由 `expected +/- tolerance` 计算。
- `equal/notEqual`：数值比较写入 `expected +/- tolerance`；容差为 0 时上下限相同。
- `greater/greaterOrEqual`：写入下限。
- `less/lessOrEqual`：写入上限。
- 旧报告只有 `comparison/expected/tolerance` 时，导出器也会反推对应上下限。
- `contains/startsWith/endsWith/isTrue` 等没有数值上下限的语义，不伪造上下限。
- Limit 的实测值表达式解析失败时，实测值保持空白，结果和错误码保持 `ERROR`；
  但脚本中已经配置的比较方式、期望值和可推导上下限仍写入 CSV，避免故障报告丢失判定标准。

## 7. 文件命名与归档

- 文件基础名优先使用 SN；无 SN 时使用 `yyyyMMdd_HHmmss_zzz`。
- 输出根目录由 Station 的 `reportOutputDirectory` 决定，留空为程序目录下 `log`。
- 下一层按 `yyyyMMdd` 建日期目录，并预建 `PASS`、`FAIL`。
- 运行中 TXT/CSV 位于日期目录根部；XLSX 在运行结束时生成。
- 正常 Pass 移入 `PASS`；其余终态（包括 Stop/Abort）移入 `FAIL`。
- 运行中关闭 UI 时只关闭文件句柄，文件仍留在日期目录根部。
- 同名文件自动加序号，不覆盖已有报告。

## 8. 明确不包含

- Checkpoint/Session 恢复状态；
- JSON 历史文件不包含 DLL 内部实时日志和 RuntimeEvent 时间线；这些内容保存在对外 TXT。
- 设备连接句柄、Host 进程和资源租约；
- UI 布局或筛选条件。
