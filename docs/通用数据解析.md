# PicoATE 通用数据解析

## 1. 设计目的

通信插件只负责收发真实数据，解析步骤负责把原始数据转换成可判断的值。

典型流程为：

```text
CAN / Modbus / VISA / Serial 插件读取原始数据
    -> 内置解析步骤
    -> outputs.value
    -> Limit、Break If、Condition Loop 或后续业务步骤
```

解析能力属于 Core 内置模块 `builtin.data-parser`，不依赖任何设备连接，也不需要额外 DLL。它通过普通 Action Step 执行，因此可以放进 TestItem、Loop 和资源事务区间，并使用标准结果仓库、实时日志、Retry 和错误策略。

解析模块只处理已经收到的数据，不负责打开设备、发送命令、等待响应、校验通信超时或持有设备 Session。这些职责仍由对应设备插件承担。

解析和判定是两个明确步骤：解析 Step 只负责把原始数据变成可复用输出，Limit Step
负责期望值、上下限和 Pass/Fail。不要在解析器里暗藏产品判定规则。工程师可以把两者放在
同一个 TestItem 中，运行前 UI 会直接展示 Limit 的判定规格，执行后再填入解析得到的
Actual。这样同一个解析结果既能参与多个判断，也能供后续业务步骤继续使用。

## 2. Flow 中的入口

Admin 模式的 Flow Editor 中增加：

```text
Basic Functions
    Data Parsing
        Decode Binary Field
        Decode Modbus Registers
        Extract Text Between
        Split Text Field
        Regular Expression Capture
```

这些功能不要求选择 Target Device。Source 通常使用表达式引用前一步插件输出，例如：

```text
${step:read-can.outputs.data}
${step:read-registers.outputs.registers}
${step:query-dmm.outputs.response}
```

所有解析函数至少输出：

| 输出 | 含义 |
| --- | --- |
| `outputs.value` | 已转换、可直接参与 Limit 判断的值 |
| `outputs.rawValue` | 转换前的原始数值，二进制和寄存器解析提供 |
| `outputs.rawHex` | 实际参与解析的字节，二进制和寄存器解析提供 |
| `outputs.text` | 截取到的原始文本，文本解析提供 |

解析失败返回 `Error`，不会使用 `0`、空字符串等假值继续执行。

## 3. CAN 和二进制字段解析

函数：`decodeBinary`

适用于 CAN 数据帧、串口二进制帧以及其他字节数组。

```json
{
  "kind": "action",
  "moduleId": "builtin.data-parser",
  "function": "decodeBinary",
  "inputs": {
    "source": "${step:read-can.outputs.data}",
    "offset": 2,
    "length": 2,
    "unit": "byte",
    "dataType": "unsigned",
    "byteOrder": "big",
    "scale": 0.1,
    "valueOffset": -40
  }
}
```

计算结果为：

```text
value = rawValue * scale + valueOffset
```

### 3.1 Source 支持形式

| 形式 | 示例 |
| --- | --- |
| 字节数组 | `[1, 2, 255]` |
| 十六进制字符串 | `"01 02 FF"`、`"0x01,0x02,0xFF"` |
| 普通文本 | 配置 `sourceFormat: "text"` 后按 UTF-8、Latin-1 或 ASCII 转字节 |

`sourceFormat` 使用 `auto` 时，会优先把完整的偶数位十六进制字符串识别成字节；普通字符串按文本处理。纯数字文本需要按文本处理时，应明确选择 `text`。

### 3.2 字段参数

| 参数 | 含义 |
| --- | --- |
| `offset` | 起始字节或起始位，从 0 开始 |
| `length` | 字节数或位数；字节模式下 0 表示按类型或剩余数据推导 |
| `unit` | `byte` 或 `bit` |
| `dataType` | `unsigned`、`signed`、`float32`、`float64`、`boolean`、`hex`、`text`、`bcd` |
| `byteOrder` | `big` 或 `little` |
| `bitOrder` | `lsb0` 表示每字节最低位是 Bit 0；`msb0` 表示最高位是 Bit 0 |
| `scale` | 比例系数，默认 1 |
| `valueOffset` | 工程值偏移，默认 0 |

位模式支持 1 至 64 位，只允许整数、布尔和十六进制输出。浮点数必须按 4 字节或 8 字节解析。

## 4. Modbus 寄存器解析

函数：`decodeRegisters`

```json
{
  "kind": "action",
  "moduleId": "builtin.data-parser",
  "function": "decodeRegisters",
  "inputs": {
    "source": "${step:read-holding-registers.outputs.registers}",
    "registerOffset": 0,
    "dataType": "float32",
    "layout": "normal",
    "scale": 1.0,
    "valueOffset": 0.0
  }
}
```

Source 可以是 0 至 65535 的整数数组，也可以是用空格、逗号、分号或冒号分隔的寄存器文本。

支持的数据类型：

```text
uint16 / int16
uint32 / int32 / float32
uint64 / int64 / float64
```

支持四种常见寄存器排列：

| Layout | 字节顺序 | 常见叫法 |
| --- | --- | --- |
| `normal` | ABCD | 大端字节、大端字序 |
| `swapBytes` | BADC | 每个寄存器内换字节 |
| `reverseWords` | CDAB | 换寄存器字序 |
| `reverseAll` | DCBA | 字节整体反转 |

不同 PLC 和仪表对“大小端”的称呼经常不一致，工程配置应以厂家协议中的实际字节排列为准。

## 5. 起止符截取

函数：`extractBetween`

串口收到：

```text
SN:1234567890\r\n
```

配置：

```json
{
  "source": "${step:read-serial.outputs.text}",
  "startMarker": "SN:",
  "endMarker": "\\r\\n",
  "occurrence": 1,
  "trim": true,
  "outputType": "string"
}
```

输出：

```text
outputs.value = "1234567890"
```

标记支持 `\r`、`\n`、`\t`、`\0`、`\\`、`\xNN` 和 `\uNNNN` 转义。起始或结束标记可以包含中文及其他 UTF-8 字符。

起始标记留空表示从文本开头取值；结束标记留空表示取到文本末尾。`occurrence` 用于选择第几次出现的起始标记。

## 6. 分隔符取列

函数：`splitText`

例如 VISA 返回：

```text
OK,25.75,V
```

配置 `delimiter=","`、`fieldIndex=1`、`outputType="number"` 后，`outputs.value` 为数值 `25.75`。

`fieldIndex` 从 0 开始；负数从末尾倒数，`-1` 表示最后一列。空字段不会被自动丢弃。

### 一次解析多个命名字段

将 `Parse Mode` 选择为 `Multiple Named Fields`，然后在命名输出表中配置字段位置、输出名称和类型。例如收到：

```text
BTSN001,812.5,0x1A
```

对应 JSON 为：

```json
{
  "source": "BTSN001,812.5,0x1A",
  "delimiter": ",",
  "resultMode": "multiple",
  "fields": [
    { "index": 0, "name": "SN1", "type": "string" },
    { "index": 1, "name": "voltage", "type": "number" },
    { "index": 2, "name": "status", "type": "hex" }
  ]
}
```

执行后产生：

```json
{
  "fields": {
    "SN1": "BTSN001",
    "voltage": 812.5,
    "status": "0x1A"
  },
  "fieldCount": 3,
  "namedFieldCount": 3
}
```

后续 Step 的 `fx` 菜单会直接显示 `SN1`、`voltage` 和 `status`。选择后分别插入：

```text
${step:解析步骤ID.outputs.fields.SN1}
${step:解析步骤ID.outputs.fields.voltage}
${step:解析步骤ID.outputs.fields.status}
```

这些是当前解析 Step 的命名输出，不会写入共享全局变量。结果仍按 UUT、Frame 和 Attempt 隔离，多 UUT、Loop 和 Retry 不会互相串值。

## 7. 正则捕获

函数：`regexCapture`

用于文本结构不完全固定、但存在稳定模式的情况：

```json
{
  "source": "TEMP=27.5C;TEMP=28.0C",
  "pattern": "TEMP=([0-9.]+)C",
  "captureGroup": 1,
  "occurrence": 2,
  "outputType": "number"
}
```

输出第二次匹配的 `28.0`。正则表达式无效、捕获组超出范围或指定次数不存在时均返回明确错误。

正则同样支持一次返回多个命名捕获组。将 `Parse Mode` 选择为 `Multiple Named Captures`：

```json
{
  "source": "SN=BTSN009,V=799.5,OK=1",
  "pattern": "SN=([^,]+),V=([0-9.]+),OK=(\\d+)",
  "resultMode": "multiple",
  "fields": [
    { "group": 1, "name": "serialNumber", "type": "string" },
    { "group": 2, "name": "voltage", "type": "number" },
    { "group": 3, "name": "ok", "type": "boolean" }
  ]
}
```

后续可以通过 `${step:解析步骤ID.outputs.fields.serialNumber}` 等表达式读取。捕获组 `0` 表示完整匹配内容，`1` 开始表示正则中的第一个括号捕获组。

命名输出名称必须以字母或下划线开头，只能包含字母、数字和下划线，并且同一个解析 Step 内不允许重名。字段位置越界、捕获组不存在或任一字段类型转换失败时，整个解析 Step 返回明确的 Error，不会留下部分成功、部分陈旧的结果。

## 8. 文本输出类型

三个文本解析函数统一支持：

| Output Type | 行为 |
| --- | --- |
| `string` | 保留为字符串 |
| `integer` | 转为有符号整数 |
| `unsigned` | 转为无符号整数 |
| `number` | 转为浮点数，支持科学计数法 |
| `boolean` | 支持 true/false、1/0、on/off、yes/no、pass/fail |
| `hex` | 解析为十六进制数并输出 `0x...` |

整数可选择自动、十进制、十六进制或二进制。自动模式识别 `0x` 和 `0b` 前缀。

## 9. 错误与诊断日志

常见错误码：

| 错误码 | 含义 |
| --- | --- |
| `ParserSourceMissing` | 未配置 Source |
| `ParserSourceTypeError` | Source 类型或内容无法转换 |
| `ParserConfigurationError` | 参数组合不合法 |
| `ParserRangeError` | offset、length、寄存器或列索引越界 |
| `ParserMarkerNotFound` | 起始或结束标记不存在 |
| `ParserPatternNotFound` | 正则指定的匹配次数不存在 |
| `ParserRegexInvalid` | 正则表达式本身无效 |
| `ParserConversionError` | 截取成功，但无法转为指定输出类型 |

成功时实时日志会包含字段位置、类型、原始十六进制值和最终值；失败时日志包含错误码和原因，方便判断是通信数据不对还是解析配置不对。

## 10. 暂不内置的能力

第一版刻意不把所有协议细节都塞进通用解析器：

- CAN ID、DLC、过滤和接收超时仍由 CAN 插件处理。
- Modbus 地址、功能码、异常码和 CRC 由 Modbus 插件处理。
- VISA 的 SCPI 命令发送、终止符设置和设备 Session 由 VISA 插件处理。
- Serial 的波特率、数据位、校验位、帧接收和超时由 Serial 插件处理。
- 厂家私有帧、多层 TLV、加密数据和专用校验算法放在业务插件中。

后续如果真实项目反复出现，可继续增加友好的通用步骤，例如 Key/Value 表解析、定长文本字段、位掩码映射、枚举值映射、校验和/CRC 验证和 JSON Path 提取。正则已经能覆盖一部分场景，但不会强迫现场工程师用复杂正则完成所有工作。

## 11. 可运行示例

示例文件：`examples/data_parser_sequence.json`

它覆盖：

- CAN Float32 字段解析并做 Limit 判断；
- 串口起止符截取 SN 并做相等判断；
- Modbus 两寄存器 Float32 解析；
- VISA 逗号文本取列；
- 正则取第二次温度值；
- Setup、Main、Cleanup 完整生命周期。
