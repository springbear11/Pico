# 盛弘充电桩 Modbus TCP 寄存器映射参考

> 来源：`寄存器映射表.xlsx`
> 生成目的：供 ATE 脚本、Modbus 插件和数据解析配置快速查阅。
> 地址、寄存器数量、数据类型、读写属性和原始说明均来自 Excel；未对协议语义做臆测。

## 使用约定

- 地址统一保留十六进制格式，例如 `0xA411`。
- `U16` 通常占 1 个寄存器，`U32` 通常占 2 个寄存器；实际以“寄存器数”列为准。
- FC03 读取时，`count` 等于连续寄存器数量；FC06 适用于单个 U16，FC10 适用于多个寄存器或 U32。
- `Unit ID` 以地址空间总览和设备实际配置为准：公共区通常 `0x00`，M2 区通常 `0x0F`，CCU 区通常 `0x01~0x0E`。
- 位字段中的协议位号通常从 1 开始；配置 `decodeBinary` 时需要转换为解析器使用的 0-based 偏移。

## 重点状态位配置提示

### 主机状态1 `0xA400~0xA401`

- U32，读取 `count=2`。
- `Byte1 Bit7`：水浸状态；以 0-based 字节流解析时，先取第 1 个寄存器，再按协议位定义解析。
- `Byte2 Bit6/Bit7`：门禁1/门禁2；`Byte3 Bit0`：门禁3。
- `Byte4`：主机风扇调速值，范围通常为 `0~100`，应按完整字节解析，不要按单 bit 解析。

### 主机状态2 `0xA402~0xA403`

- U32，读取 `count=2`。
- `Byte1 Bit0/Bit1/Bit2`：门禁4/门禁5/门禁6。
- `Byte2 Bit0/Bit1/Bit2`：断上级开关/急停/液位状态。
- `Byte4`：C2 风扇调速值，范围 `0~100`。

### 全自动测试阶段 `0xA410`

| 值 | 阶段 |
|---:|---|
| 0 | 工装空闲 |
| 1 | 前置条件检测中 |
| 2 | 模块地址测试中 |
| 3 | 开关反馈状态测试中 |
| 4 | 主机终端之间线缆测试中 |
| 5 | 开关驱动位置测试中 |
| 6 | 模块输出线缆测试中 |
| 7 | CAN 通信质量测试中 |
| 8 | EPO 线缆测试中 |
| 100 | 测试通过 |

### 全自动测试总结果 `0xA411~0xA412`

- U32，每两个 bit 表示一个状态：`0=未测试`、`1=通过`、`2=失败`、`3=测试中`。
- `Bit0~1`：工装前置测试。
- `Bit2~3`：模块地址测试。
- `Bit4~5`：开关反馈状态测试。
- `Bit6~7`：开关驱动位置测试。
- `Bit8~9`：主机终端之间线缆测试。
- `Bit10~11`：模块输出线缆测试。
- `Bit12~13`：EPO 线缆测试。

### M2 控制寄存器

- `0xA800`：主机风扇 PWM，U16，写入 `0~100`；50% = `0x0032`。
- `0xA80E`：干接点驱动测试1，Bit0 红灯、Bit1 绿灯、Bit2 蓝灯。
- `0xA828`：M2 全自动干接点驱动测试，Bit1~Bit6 分别使能对应测试。模块地址+开关反馈+主机终端线缆+开关驱动位置 = `0x001E`。

## 2. Unit ID 路由

同一 TCP 连接可通过 Unit ID 访问不同控制板/终端；CCU 的寄存器地址结构相同，通过 Unit ID 区分目标终端。

| 目标 | Unit ID | 用途 |
|---|---:|---|
| MCU 主控板 | `0x00` | UI、云平台、公共协议区 |
| CCU1 ~ CCU14 | `0x01 ~ 0x0E` | 终端安全与充电控制 |
| M2 | `0x0F` | 安全与功率分配 |
| 预留扩展 | `0x10 ~ 0xFE` | 预留 |
| 广播 | `0xFF` | 协议定义为等价 `0x00` |

同一 CCU 地址访问不同终端时，仅改变 Flow 中的 `unitId`；不要为每个终端重复建立 TCP 连接。

## 3. Modbus TCP 报文

Modbus TCP ADU = **MBAP（7 字节）+ PDU**。

| MBAP 字段 | 长度 | 说明 |
|---|---:|---|
| Transaction ID | 2 B | ATE 生成；请求和响应必须一致，用于匹配事务 |
| Protocol ID | 2 B | 固定 `0x0000` |
| Length | 2 B | 后续 `Unit ID + PDU` 的字节数 |
| Unit ID | 1 B | 板卡/终端路由标识 |

正常响应使用请求功能码；异常响应的功能码为请求 FC 加 `0x80`。例如 FC10 出错会返回 `0x90`。

## 4. 支持功能码

| FC | 名称 | 请求/响应 | ATE 用途 |
|---|---|---|---|
| `0x03` | Read Holding Registers | 起始地址 + 数量 / 字节数 + 原始寄存器字节 | 读取状态、配置、告警 |
| `0x10` | Write Multiple Registers | 起始地址 + 数量 + 字节数 + 数据 / 地址与数量回显 | 写 U16/U32、登录、心跳、控制 |

- 协议 V1.30 已删除 FC06；即使只写一个 U16，也使用 FC10，数量为 `1`。
- FC10 的正常响应只回显起始地址和数量，表示 UUT 接收请求；需要确认值实际生效时，仍须以 FC03 回读并做 Limit 校验。
- FC03 的插件返回应该交由 `Decode Modbus Registers` 或 `Decode Binary` 解析；MBAP 和 FC 字节不是寄存器数据。

### FC03 示例：读取两个寄存器

请求：`00 06 00 00 00 06 00 03 28 0E 00 02`

响应：`00 06 00 00 00 07 00 03 04 00 00 12 5C`

其中数据部分为 `00 00 12 5C`，按 U32 解析为十进制 `4700`。

### FC10 示例：写 U32 输出过压值

请求：`00 05 00 00 00 0B 00 10 28 0E 00 02 04 00 00 12 5C`

响应：`00 05 00 00 00 06 00 10 28 0E 00 02`

写入数据 `00 00 12 5C` 为 U32 值 `4700`；响应只回显地址与数量。

## 5. 登录、心跳和退出

### 登录

1. 使用 Unit ID `0x00`，通过 FC10 向 `0x0000` 写入 `0xA5A5`，数量为 `1`。
2. 收到 FC10 正常回显后，登录请求已被接受。
3. 可用 FC03 读取 `0x0011` 确认状态：`0=未登录`、`1=已登录`、`2=心跳超时`。

登录报文：`00 01 00 00 00 09 00 10 00 00 00 01 02 A5 A5`。

### 心跳

- 登录后设置或确认 `0x0010` 的心跳超时阈值，单位秒，默认 `30`。
- ATE 每 5 秒以 FC10 向 `0x0012` 写入递增的心跳计数器（`heartbeat++`），不建议持续写固定值 `1`。
- 心跳超时后，UUT 会将会话状态置为 `2`。

### 退出

使用 Unit ID `0x00`、FC10 向 `0x0000` 写入 `0x0000` 登出。协议说明其他认证值可能不回复，不应用于自动化脚本。

## 6. 推荐测试流程

1. 连接 UUT 的 TCP `502` 端口并复用长连接。
2. 登录并确认会话状态。
3. 在心跳有效期间执行 FC03 / FC10。
4. 写配置后若需确认效果，执行 FC03 回读、解析和 Limit 判断。
5. 测试结束或异常 Cleanup 时，登出并恢复安全状态。
6. 多 CCU 共用同一连接时，每次请求设置目标 `unitId`；不要因切换 CCU 而重复 Open/Close。

## 8. 告警位图规则

- `0x3B10 ~ 0x3B2F` 是 A 枪告警位图：32 个寄存器、64 个字节，FC03 的 `count` 配置为 `32`。
- 每字节中的某一位为 `1` 表示该告警发生；允许多个告警同时出现。
- 前 24 B 为 CCU 故障，25~28 B 为 MCU 预留，29~32 B 为交流桩预留；主机相关告警从协议位置 `33.x` 起。
- `Decode Binary` 使用 0-based 偏移，协议中从 1 开始编号的字节/位需要先换算。

| 协议位置 | 主机告警 |
|---|---|
| `39.1 ~ 39.4` | 主机防雷器 1 ~ 4 故障 |
| `40.8` | 主机水浸故障 |
| `41.3` | 主机输入过压 |
| `41.4` | 主机输入欠压 |
| `41.5` | 主机输入电压高 |
| `41.6` | 主机输入电压低 |

## 10. ATE 配置检查清单

- 连接：`resource` 使用 UUT IP/端口，测试期间优先复用 TCP 长连接。
- 路由：公共/MCU 用 `0x00`，M2 用 `0x0F`，CCU 用 `0x01~0x0E`。
- 功能码：读用 FC03，写用 FC10，不要用 FC06。
- 数量：`count` 是寄存器数而不是字节数；`char[64]` 读取 `32` 个寄存器。
- U32：按两个寄存器、高字在前写入；FC10 回显不等于值已实际生效。
- 解析：明确寄存器偏移、字节序及 0-based 位偏移，避免 `ParserRangeError`。
- 会话：登录后使用递增心跳；异常与 Cleanup 处理登出和安全状态。
- 异常：FC03 异常会显示 `0x83`，FC10 异常会显示 `0x90`；后续异常码决定原因。
